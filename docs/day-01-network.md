# Day 1 — 네트워크 계층

> 목표: EKS가 올라갈 **VPC 네트워크**를 이해하고 직접 만든다.
> K8s를 켜기 전, 순수 AWS 인프라 계층을 먼저 다진다.

## 왜 네트워크부터?

EKS 클러스터는 반드시 **기존 VPC의 서브넷 위에** 올라갑니다. 컨트롤플레인도, 워커
노드도, 파드도 결국 이 서브넷의 IP를 사용합니다. 그래서 네트워크 구조를 모르면
그 위의 모든 것이 "마법"처럼 느껴집니다. 오늘 이 계층을 손으로 만들면 이후가 쉬워집니다.

## 오늘 만드는 구조

```
                    인터넷
                      │
                 ┌────┴────┐
                 │   IGW   │
                 └────┬────┘
        VPC 10.0.0.0/16
   ┌──────────────────┴───────────────────┐
   │  AZ: 2a                  AZ: 2c       │
   │  ┌─────────────┐        ┌───────────┐ │
   │  │ public /20  │        │ public /20│ │  ← 로드밸런서, NAT 위치
   │  │  [NAT GW]───┼────────┼──> IGW    │ │
   │  └──────┬──────┘        └───────────┘ │
   │         │ (프라이빗의 외부행 트래픽)     │
   │  ┌──────┴──────┐        ┌───────────┐ │
   │  │ private /20 │        │private /20│ │  ← 워커 노드 / 파드 위치
   │  └─────────────┘        └───────────┘ │
   └───────────────────────────────────────┘
```

## 핵심 개념

| 리소스 | 역할 | 비유 |
|--------|------|------|
| **VPC** | 격리된 사설 네트워크 (CIDR로 IP 대역 정의) | 우리 회사 건물 전체 |
| **서브넷** | VPC를 AZ별로 쪼갠 IP 구획 | 건물의 각 층 |
| **IGW** | VPC ↔ 인터넷 양방향 관문 | 건물 정문 |
| **NAT GW** | 프라이빗 → 인터넷 **단방향** 출구 | 직원 전용 후문(밖으로만) |
| **라우트 테이블** | "이 목적지는 저 게이트웨이로" 규칙 | 건물 내부 이정표 |

### 퍼블릭 vs 프라이빗 서브넷의 진짜 차이
서브넷 자체엔 "퍼블릭/프라이빗" 속성이 없습니다. **어떤 라우트 테이블에 연결됐는지**가
차이를 만듭니다.
- 라우트 테이블의 `0.0.0.0/0` → **IGW** 를 가리키면 → 퍼블릭
- 라우트 테이블의 `0.0.0.0/0` → **NAT** 를 가리키면 → 프라이빗

### 워커 노드는 왜 프라이빗에?
외부에서 노드로 직접 들어오는 경로를 막아 공격면을 줄입니다. 노드는 이미지 pull 등
바깥으로 나가는 통신만 NAT를 통해 하고, 사용자 트래픽은 퍼블릭 서브넷의 로드밸런서가
받아서 안으로 전달합니다.

### EKS 서브넷 태그
- 퍼블릭: `kubernetes.io/role/elb = 1` → 외부 로드밸런서(ALB) 배치 대상
- 프라이빗: `kubernetes.io/role/internal-elb = 1` → 내부 로드밸런서 배치 대상

지금 당장은 안 쓰지만, Day 8에서 Load Balancer Controller가 이 태그를 보고 서브넷을
자동으로 찾습니다. 미리 붙여둡니다.

## 실습 순서

> 아래는 terraform 명령을 직접 쓰는 형태입니다. 평소에는 리포 루트에서
> `make init / plan / apply / destroy`로 더 짧게 실행할 수 있습니다.

```bash
cd terraform

# 1) 초기화 — S3 백엔드 연결 + provider 다운로드 (기기당 1회)
terraform init

# 2) 코드 형식/문법 점검 (선택이지만 습관 들이면 좋음)
terraform fmt
terraform validate

# 3) 무엇이 만들어질지 미리보기 — apply 전에 꼭 읽어보기!
terraform plan

# 4) 실제 생성
terraform apply
#   → "Plan: 14 to add" 확인 후 yes
#   (VPC 1 + IGW 1 + 서브넷 4 + EIP 1 + NAT 1 + 라우트테이블 2 + 연결 4)

# 5) 콘솔/CLI로 관찰
terraform output
aws ec2 describe-subnets \
  --filters "Name=vpc-id,Values=$(terraform output -raw vpc_id)" \
  --query "Subnets[].{Name:Tags[?Key=='Name']|[0].Value,CIDR:CidrBlock,AZ:AvailabilityZone}" \
  --output table

# 6) 오늘 학습 끝 — 반드시 정리 (NAT/EIP도 과금됨)
terraform destroy
```

## 관찰 포인트 (이해했는지 스스로 점검)

1. `terraform plan`에서 몇 개의 리소스가 생성되나요? 각각 무엇인가요?
2. 퍼블릭 서브넷 2개와 프라이빗 서브넷 2개의 CIDR이 겹치지 않는지 확인해 보세요.
3. NAT 게이트웨이가 왜 퍼블릭 서브넷에 있어야 하는지 설명할 수 있나요?
4. 프라이빗 라우트 테이블의 `0.0.0.0/0`이 어디를 가리키는지 콘솔에서 확인해 보세요.

## 비용 메모
- **NAT 게이트웨이**: 시간당 약 $0.045 + 데이터 처리 요금. 오늘 구조에서 가장 큰 비용원.
- **EIP**: NAT에 붙어 사용 중이면 무료, 안 붙어 방치되면 과금.
- 그래서 **`terraform destroy`로 세션을 마무리**하는 습관이 중요합니다.
